一、项目定位
------------
Android 监听端用于监听微信、支付宝到账通知，提取收款金额，并推送到 VMQ Server。

三、使用步骤
------------
1. 部署 VMQ Server
   推荐使用仓库根目录 docker-compose.yml：
   cp .env.example .env
   docker compose up -d --build

2. 安装 APK
   构建命令：
   ./scripts/build-android.sh
   APK 输出：
   android/app/build/outputs/apk/debug/app-debug.apk

3. 授权通知使用权
   设置 → 应用 → 特殊权限 → 通知使用权 → 启用 V免签 / VMQ

4. 配置服务端
   方式1：扫码配置（推荐）
   方式2：手动输入服务器地址和通讯密钥

5. 测试心跳
   点击“检测心跳”，确认能访问后台。

6. 测试监听
   点击“检测监听”，确认通知监听权限正常。

7. 完成防杀后台设置
   - 关闭电池优化
   - 锁定后台
   - 允许自启动
   - 确认 VMQ、微信、支付宝通知权限开启

8. 真实测试
   使用微信/支付宝收款码做小额测试，并在后台查看订单和日志。

四、如何监听支付
----------------
1. 通知监听
   NotificationListenerService.onNotificationPosted()

2. 包名识别
   微信：com.tencent.mm
   支付宝：com.eg.android.AlipayGphone

3. 关键词匹配
   微信：微信支付、微信收款助手、微信收款商业版等
   支付宝：通过扫码向你付款、成功收款、收钱码收款通知等

4. 金额提取
   通过多级正则匹配提取通知内容中的金额。

5. HTTP 推送
   调用 VMQ Server /appPush，并携带 MD5 签名。

五、如何保活 App
----------------
1. 前台服务
   显示持久通知，系统优先级更高。

2. NotificationListenerService
   系统通知监听服务，需要用户授权通知使用权。

3. WakeLock
   防止息屏后 CPU 完全休眠。

4. 心跳线程
   每 30 秒左右向服务器发送心跳。

5. 开机自启动
   BootReceiver 监听 BOOT_COMPLETED。

6. 服务自动重连
   通知监听断开时主动 requestRebind。

六、调试方法
------------
推荐优先使用 App 内“查看运行日志”。

ADB 调试：
adb logcat -s VmqNotification:D MainActivity:D BootReceiver:D PaymentAccessibilityService:D

关键日志：
- NotificationListener 已连接
- 心跳成功
- 心跳失败
- 微信 / 支付宝新通知捕获
- 收款金额提取成功
- 推送响应: success
- 去重跳过

七、常见问题
------------
Q: 监听不生效？
A: 检查通知使用权；关闭后重新开启；重启 App；必要时重启手机。

Q: 收款后没有回调？
A: 查看 App 内运行日志，确认是否识别到通知、是否推送成功、后台地址和通讯密钥是否正确。

Q: 心跳失败？
A: 确认 VMQ Server 可访问，手机网络正常，服务端地址协议/端口正确，通讯密钥一致。

Q: 服务频繁被杀？
A: 关闭电池优化、锁定后台、允许自启动，检查厂商管家/安全中心限制。

Q: 金额识别错误？
A: 复制 App 内运行日志，检查通知原文和金额提取过程；必要时更新关键词或正则。

八、厂商特殊设置
----------------
小米 / Redmi：
- 设置 → 应用设置 → 授权管理 → 自启动管理 → 启用
- 设置 → 电池与性能 → 无限制
- 最近任务 → 锁定应用

华为 / 荣耀：
- 设置 → 电池 → 应用启动管理 → 手动管理
- 允许自启动、允许后台活动、允许关联启动

OPPO / 一加：
- 设置 → 电池 → 应用耗电管理 → 允许后台运行
- 设置 → 应用 → 自启动管理 → 允许

vivo / iQOO：
- i管家 → 应用管理 → 自启动 → 启用
- 设置 → 电池 → 后台高耗电 → 允许

三星：
- 设置 → 电池 → 后台使用限制 → 移出限制列表
- 设置 → 应用 → 电池 → 不受限

十、注意事项
------------
1. 通知监听权限敏感，请在可信设备使用。
2. 建议通过 HTTPS 访问 VMQ Server。
3. 默认后台账号和通讯密钥部署后必须修改。
4. 本项目仅供学习、测试和个人自用，请勿用于违法用途。
