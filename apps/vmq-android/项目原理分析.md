# VMQ / V免签 Android 监听端项目原理分析

本文档分析 `android/` 监听端的核心原理、保活策略、服务端交互和当前整理版增强内容。

## 1. 系统整体流程

```text
1. 用户在业务系统创建订单
   ↓
2. 业务系统调用 VMQ Server /createOrder
   ↓
3. VMQ Server 生成订单和实际应付金额
   ↓
4. 用户使用微信/支付宝付款
   ↓
5. Android 监听端收到到账通知
   ↓
6. Android 监听端识别金额并调用 /appPush
   ↓
7. VMQ Server 根据支付类型和金额匹配订单
   ↓
8. VMQ Server 标记订单完成并回调业务系统 notifyUrl
```

## 2. 通知监听原理

核心类：

```text
NeNotificationService2.java
```

该类继承 Android 系统服务：

```java
NotificationListenerService
```

用户授权“通知使用权”后，系统会在收到通知时回调：

```java
onNotificationPosted(StatusBarNotification sbn)
```

监听端从通知中读取：

- 包名
- 标题
- 内容
- 附加文本
- 时间

然后根据包名和关键词判断是否为收款通知。

## 4. 金额提取

监听端从通知文本中通过多级规则提取金额。

典型场景：

```text
张三通过扫码向你付款49.95元
```

提取结果：

```text
49.95
```

整理版已增强金额识别和异常日志，方便在支付平台通知格式变化时排查。

## 5. 服务端推送 `/appPush`

识别到账金额后，监听端调用 VMQ Server：

```text
GET /appPush
```

关键参数：

| 参数 | 说明 |
| --- | --- |
| `type` | `1=微信`，`2=支付宝` |
| `price` | 识别到的到账金额 |
| `t` | 时间戳 |
| `sign` | MD5 签名 |

签名规则：

```text
sign = md5(type + price + t + key)
```

其中 `key` 是后台通讯密钥。

服务端收到后根据 `type + price` 匹配待支付订单。

## 6. 心跳 `/appHeart`

监听端会定期向 VMQ Server 发送心跳：

```text
GET /appHeart
```

作用：

- 后台展示监听端在线状态
- 帮助保持网络活跃
- 便于排查 App 是否还在运行

签名规则：

```text
sign = md5(t + key)
```

## 7. 保活策略

Android 系统会严格限制后台应用，因此监听端采用多种策略提高稳定性。

### 7.1 前台服务

通过 `startForeground()` 显示常驻通知：

```text
正在监听收款通知
```

前台服务比普通后台进程更不容易被系统杀死。

### 7.2 WakeLock

使用 `PARTIAL_WAKE_LOCK`，降低息屏后 CPU 完全休眠导致监听中断的概率。

### 7.3 通知监听服务自动重连

当系统回调：

```java
onListenerDisconnected()
```

监听端会尝试重新绑定通知监听服务。

### 7.4 开机自启动

`BootReceiver` 监听开机广播，设备重启后尝试恢复监听能力。

### 7.5 厂商后台设置

App 内提供防杀后台设置入口，引导用户完成：

- 关闭电池优化
- 允许自启动
- 锁定后台
- 确认通知权限

## 8. 可选无障碍增强模块

核心类：

```text
PaymentAccessibilityService.java
```

设计边界：

- 仅在用户手动开启无障碍权限后运行。
- 仅用于感知微信/支付宝/本应用前台状态并给出可见状态提醒。
- 不读取聊天或支付窗口内容。
- 不执行自动点击。
- 不代替用户授权。

它不是收款识别的核心链路；核心收款识别仍依赖通知监听。

## 9. 应用内运行日志

核心类：

```text
LogStore.java
```

整理版新增 App 私有运行日志，用于排障。

记录内容包括：

- App 启动
- 扫码配置 / 手动配置
- 心跳成功 / 失败
- 通知监听连接 / 断开
- 收款通知识别
- 金额提取
- 推送成功 / 失败
- WakeLock 申请 / 释放
- 开机自启事件
- 无障碍服务状态

主界面入口：

```text
查看运行日志
```

支持：

- 查看
- 复制
- 清空

> 普通 Android App 不能读取全系统 logcat。该日志只记录本 App 自己的关键运行链路。

## 10. 配置方式

监听端需要配置：

- VMQ Server 地址
- 通讯密钥 `key`

配置方式：

1. 扫码配置：扫描后台监控端设置页二维码。
2. 手动配置：输入服务器地址和通讯密钥。

配置保存后，点击“检测心跳”验证连接。

## 12. 安全边界

- 通知监听权限敏感，仅建议在可信设备使用。
- 建议通过 HTTPS 访问 VMQ Server。
- 通讯签名为旧式 MD5 拼接，正式部署建议配合 HTTPS、IP 限制和访问控制。
- 后台默认账号和默认通讯密钥部署后必须修改。
- 本项目仅供学习、测试和个人自用，请勿用于违法用途。

## 13. 排障路径

### 收款后没回调

1. 查看 App 内运行日志是否捕获到通知。
2. 检查是否识别出正确金额。
3. 检查 `/appPush` 是否返回成功。
4. 查看 VMQ Server 日志是否匹配订单。
5. 查看业务系统 `notifyUrl` 是否收到回调并返回 `success`。

### 心跳失败

1. 手机网络是否正常。
2. 后台域名 / IP / 端口是否可访问。
3. 后台是否已启动。
4. 通讯密钥是否一致。
5. 反向代理是否正确转发。

### 服务被杀

1. 常驻通知是否还在。
2. 电池优化是否关闭。
3. 后台是否锁定。
4. 自启动是否允许。
5. 厂商安全中心是否限制后台联网。
